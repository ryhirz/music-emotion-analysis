# 数据集选型对比：GTZAN vs DEAM

> 决策文档 · 2026-09-01
> 背景：项目核心目标是「音乐**情感**分析」，不是曲风分类。选型的关键分歧点正在于此。

---

## 一、结论先行

| | GTZAN | DEAM |
|---|---|---|
| **情感标签** | ❌ **没有**，只有曲风 | ✅ **有**（valence / arousal 连续标注） |
| **与项目目标的语义匹配** | 弱（需曲风→情感人工映射） | 强（直接对应效价-唤醒度模型） |
| **上手难度** | 低（一键下载，教程极多） | 中高（需申请，国内下载常需代理） |
| **推荐度** | ⭐⭐⭐ 工程练手首选 | ⭐⭐⭐⭐⭐ 情感任务正确解 |

**我的建议（按优先级）：**

1. 如果项目标题要写「音乐**情感**分析」→ **DEAM 是技术上的正确答案**，GTZAN 的标签是"代理标签"，语义上不严谨。
2. 但考虑到你的实际情况（Python 基础一般、首次独立完成、需要尽快跑通端到端）→ **先用 GTZAN 打通全链路是合理的工程策略**。
3. **折中路线（推荐）**：用 GTZAN 快速跑通「下载→特征→模型→界面→部署」全流程，同时在项目里**诚实标注**这是基于曲风-情感映射的方法；等链路跑通后，再换 DEAM 数据重训一版作为升级点。

---

## 二、逐维度对比

### 2.1 数据规模与格式

| 维度 | GTZAN | DEAM |
|------|-------|------|
| 原始用途 | 音乐**曲风**分类（2001, Tzanetakis） | 音乐**情感**分析（2016, Aljanaki） |
| 音频数量 | 1,000 首 | 2,000 首 |
| 单条时长 | 30 秒 | 45 秒 |
| 总时长 | 约 8.3 小时 | 约 25 小时 |
| 音频格式 | `.au`（原始版）/ `.wav`（HF 版） | 多为 `.mp3` 片段 |
| 采样率 | 22050 Hz 单声道 16-bit | 44100 Hz 立体声（需自行降采样） |
| 压缩包体积 | **约 1.2 GB** | 数 GB（视版本而定） |
| 分类体系 | 10 个曲风 × 100 首（完全均衡） | 连续 V/A 值，无固定类别 |

### 2.2 标签体系（**最关键差异**）

**GTZAN —— 只有曲风，没有情感**

10 个类别：`blues, classical, country, disco, hiphop, jazz, metal, pop, reggae, rock`

用它做情感分析，必须自己定义「曲风 → 情感」的映射表，例如：

| 曲风 | 映射情感 | 依据 |
|------|----------|------|
| disco | 活力 | 高 BPM、强节拍 |
| pop | 欢快 | 明亮、中高能量 |
| rock | 激昂 | 高能量、强驱动 |
| metal | 激昂 | 极高能量 |
| hiphop | 活力 | 强节奏 |
| country | 治愈 | 温暖、中速 |
| jazz | 平静 | 舒缓、低能量 |
| classical | 平静 | 低能量、柔和 |
| reggae | 治愈 | 中低速、放松 |
| blues | 悲伤 | 小调、低沉 |

⚠️ **这个映射的隐患**：
- 模型实际学到的是**曲风声学特征**，你只是把输出的曲风名改叫了情感名
- 同一曲风内部情感差异巨大（rock 里既有激昂也有悲伤的慢摇）
- 标注是"曲风级"而非"听感级"，粒度很粗
- 面试时如果被追问「你凭什么说 disco 就是活力」，需要能自圆其说

**DEAM —— 原生情感标注**

每首歌有众包标注的连续 `(valence, arousal) ∈ [0,1]²`，正好对应需求文档第 1 节采用的 Russell 效价-唤醒度模型：

- arousal ≥ 0.5 且 valence ≥ 0.5 → 活力 / 激昂
- arousal < 0.5 且 valence ≥ 0.5 → 平静 / 治愈
- arousal < 0.5 且 valence < 0.5 → 悲伤

✅ 标签直接对应你的情感体系，**语义严谨，可解释性强**。

### 2.3 下载难度（实测）

| | GTZAN | DEAM |
|---|---|---|
| 获取方式 | HuggingFace 直链，无需注册 | 官网填表申请 + 邮件审核 |
| 国内可用性 | ✅ `hf-mirror.com` 镜像**实测可直连** | ⚠️ 学术站点，通常需要代理 |
| 实测下载速度 | 直链 1.22 GB，已验证可下载 | 未实测（官网当前网络不可达） |
| 备选源 | 多（HF / Marsyas / Kaggle） | 少（主要靠官网 + Zenodo） |

> 本次实测：GTZAN 的 `https://hf-mirror.com/datasets/marsyas/gtzan/resolve/main/data/genres.tar.gz`
> 返回 HTTP 200，`content-length: 1226192050`（1.14 GiB），国内网络可直连。

### 2.4 训练成本（无 GPU）

| | GTZAN | DEAM |
|---|---|---|
| 特征提取耗时（CPU） | 约 **30–60 分钟**（1000 × 30s） | 约 **1–2 小时**（2000 × 45s，且需降采样） |
| 特征矩阵大小 | 1000 × ~40 维（几 MB） | 2000 × ~40 维（几 MB） |
| 模型训练耗时 | **秒级**（RandomForest） | **秒级** |
| 内存占用 | 极低 | 极低 |

两者在**模型训练**环节都毫无压力，差异只在**特征提取**这一步，且都是"挂机跑一次"的量级，无 GPU 完全可行。

## 三、对简历项目的影响

| 评估维度 | GTZAN | DEAM |
|----------|-------|------|
| 端到端跑通速度 | 快（1-2 天出 Demo） | 慢（光数据获取可能卡 1-2 天） |
| 技术严谨性 | 中（标签是代理的） | 高（标签原生） |
| 面试可讲性 | 需主动说明映射逻辑与局限 | 可直接讲 V/A 映射，逻辑闭环 |
| 失败风险 | 低 | 中（卡在下载就做不下去） |

**坦率评价**：
- 用 GTZAN 做情感分析，在学术界属于"凑合用"的做法，但**作为本科生的第一个完整 ML 项目完全够格** —— 面试官看的是你能不能跑通全链路、能不能讲清取舍，而不是数据集有多前沿。
- 真正加分的是：**你能在 README 里主动指出"GTZAN 只有曲风标签，我用了曲风-情感映射作为弱监督方案，这是本项目的局限之一，下一步计划换 DEAM"**。这句话比数据集本身更能体现思考深度。

## 四、决策建议

**选 GTZAN，如果：**
- 你希望 2 周内看到可演示的成果
- 你更看重"完整跑通链路"而非"学术严谨"
- 你不想在下载数据上耗时间（DEAM 国内下载有真实风险）

**选 DEAM，如果：**
- 你有 3-4 周时间，且网络条件允许（或愿意折腾代理）
- 你希望项目在语义上无懈可击
- 你打算把这个项目写进简历的核心位置，预期会被深挖

**最稳妥的路线（推荐）：**
```
第 1 阶段（1-2 周）: GTZAN → 跑通 下载→特征→模型→界面→部署 全链路
第 2 阶段（可选升级）: 换 DEAM 重训 → 对比两版效果 → 写进 README 的"迭代记录"
```

这样即使 DEAM 下载不下来，你也有一个完整可交付的项目；如果顺利，还能多一个"数据集迭代对比"的亮点。
