## 0.5 ⚠️ Python 3.13 用户必读：装完 librosa 也不能直接用

如果你用的是 **Python 3.13**，按上面装完后，一调用 `librosa.load()` 就会报：

```
ModuleNotFoundError: No module named 'aifc'
```

**而且不管读 .wav 还是 .au 都报同样的错**。这是本项目实测踩到的真实坑，排查过程如下：

**根因链条：**

```
librosa.load(音频路径)
  └─ librosa/core/audio.py 第 170 行：
       if isinstance(path, tuple(audioread.available_backends()))
         └─ audioread/__init__.py：available_backends() 内部 from . import rawread
              └─ audioread/rawread.py 第 16 行：import aifc   ← 就是这里炸了
```

`aifc`（以及 `sunau`、`chunk`、`audioop` 等）在 **Python 3.13 中被从标准库移除**（PEP 594「清理死亡电池」）。
`audioread` 还没完全适配，于是 `librosa.load()` 这个函数**整个不可用**。

**解决办法（官方回溯包，一句话搞定）：**

```bash
pip install standard-aifc standard-sunau -i https://pypi.tuna.tsinghua.edu.cn/simple
```

这两个包是 Python 官方把被删掉的 stdlib 模块单独发布到 PyPI 的版本，装上后 `import aifc` 就能正常工作。

**验证修复是否生效：**

```bash
python -c "import aifc, sunau; print('补丁生效')"
python -c "import librosa; y,sr = librosa.load(librosa.ex('trumpet'), duration=1.0); print('音频加载成功:', len(y), '个采样点')"
```

**其他选择：**

| 方案 | 说明 |
|------|------|
| 装回溯包（推荐） | `pip install standard-aifc standard-sunau`，改动最小 |
| 降级到 Python 3.11 | 标准库里 aifc/sunau 都还在，生态最成熟，适合想彻底省心的人 |
| 升级 librosa 到 0.11+ | 新版本可能已修复，但未实测，且可能引入其他 API 变动 |

> `requirements.txt` 里已包含这两个补丁包，正常走第 0 节流程即可自动装上。
> 只有当你自己一个个手装依赖时，才需要单独补这一步。

## 1. Python 版本怎么选（重要，别踩坑）

本项目用到 **numba**（librosa 的重采样依赖它），而 numba 对 Python 版本非常敏感 —— 新 Python 刚发布时 numba 往往还没跟上，会导致装不上或运行时报错。

| Python 版本 | 结论 | 配套版本组合 |
|-------------|------|--------------|
| **3.13** | ✅ 可用（本项目实测通过） | numpy 2.1.3 + numba 0.61.0 + scipy 1.14.1 |
| **3.11** | ✅ 最稳妥（生态最成熟） | numpy 1.26.4 + numba 0.59.1 + scipy 1.11.4 |
| 3.12 | ✅ 可用 | numpy 1.26.4 + numba 0.60.0 |
| 3.10 及以下 | ⚠ 部分新版包已不再支持 | 不推荐 |

**建议**：你当前的 Python 是 3.13，`requirements.txt` 里的组合已经实测能装能跑，**直接用即可，不用折腾降级**。
只有当你遇到莫名其妙的 numba 报错时，再考虑装 Python 3.11 走"最稳妥组合"。

查看当前 Python 版本：

```bash
python --version
```

## 3. 必须额外装的系统软件：ffmpeg

### 为什么需要它

`librosa` 读 **wav / au / flac** 靠 soundfile，不需要 ffmpeg。
但读 **mp3** 必须靠 ffmpeg。你的项目目标是"用户上传 mp3/wav"，所以 **mp3 支持是刚需**。

> 好消息：GTZAN 数据集是 .au 或 .wav 格式，**数据集准备阶段可以先不装 ffmpeg**。
> 等你做到"支持用户上传 mp3"那一步再装也来得及。

### 各系统安装方法

**Windows（三选一）：**

```powershell
# 方式 1：winget（Win10 1709+ 自带，最简单）
winget install ffmpeg

# 方式 2：Chocolatey（如果你装了 choco）
choco install ffmpeg

# 方式 3：手动安装
#   1. 打开 https://www.gyan.dev/ffmpeg/builds/
#   2. 下载 ffmpeg-release-essentials.zip
#   3. 解压到 C:\ffmpeg
#   4. 把 C:\ffmpeg\bin 加到系统环境变量 PATH
#   5. 重启终端
```

**Mac：**

```bash
brew install ffmpeg
```

**Linux：**

```bash
# Debian / Ubuntu
sudo apt-get update && sudo apt-get install -y ffmpeg

# Fedora / RHEL / CentOS
sudo dnf install -y ffmpeg
# 或：sudo yum install -y ffmpeg

# Arch / Manjaro
sudo pacman -S ffmpeg
```

**验证是否装好：**

```bash
ffmpeg -version
```

能输出版本号就说明装好了。

## 4. libsndfile 报错解决方案（重点）

### 这个报错长什么样

```
OSError: sndfile library not found
```
或
```
RuntimeError: Failed to load libsndfile
```
或
```
ImportError: DLL load failed while importing _soundfile: 找不到指定的模块。
```

**原因**：`soundfile` 是 Python 对 C 语言库 `libsndfile` 的封装。Python 包本身装上了，但它依赖的 C 动态库（Windows 是 `.dll`、Mac 是 `.dylib`、Linux 是 `.so`）没找到。

### 先做这个诊断（三系统通用）

```bash
python -c "import soundfile; print('libsndfile 版本：', soundfile.__libsndfile_version__)"
```

能打印出版本号 → 已经好了，不用往下看。
报错 → 按下面对应系统的方案处理。

---

### Windows 解决方案

**方案 1（先试这个，成功率最高）：强制重装 soundfile**

正常安装的 soundfile wheel 里**已经打包了** libsndfile 的 DLL，重装通常能修复文件损坏或缺失。

```bash
pip install --force-reinstall --no-cache-dir soundfile
python -c "import soundfile; print(soundfile.__libsndfile_version__)"
```

**方案 2：确认没有 32/64 位混装**

```bash
python -c "import struct; print('你的 Python 是', struct.calcsize('P')*8, '位')"
```

输出必须是 `64 位`。如果是 32 位，说明你装了 32 位 Python，卸载重装 64 位版本。

**方案 3：手动放 DLL**

1. 打开 https://github.com/libsndfile/libsndfile/releases
2. 下载 `libsndfile-1.2.2-win64.zip`（版本号可能更新，选最新的 win64）
3. 解压，找到 `bin\libsndfile-1.dll`
4. 把这个 dll 复制到下面**任意一个**位置：
   - `C:\Windows\System32\`
   - 你的虚拟环境目录 `.venv\Scripts\`
   - 或者把 dll 所在文件夹加入系统 PATH

**方案 4：换 conda（终极方案）**

```bash
conda install -c conda-forge libsndfile soundfile
```

conda 会自动处理动态库路径，基本一次成功。

---

### macOS 解决方案

**方案 1：用 Homebrew 装底层库**

```bash
# 装 libsndfile（核心）
brew install libsndfile

# 顺手把常见音频格式支持也装上
brew install flac libogg libvorbis opus mpg123

# 强制重装 Python 包，让它重新链接到底层库
pip install --force-reinstall --no-cache-dir soundfile
```

**方案 2：Apple Silicon (M1/M2/M3) 特别注意**

如果你用的是 M 系列芯片，且 pip 装的是 x86 版本的包（通过 Rosetta 运行），会出现架构不匹配：

```bash
# 检查 Python 架构，应输出 arm64
python -c "import platform; print(platform.machine())"
```

如果输出 `x86_64`，说明你在用 Rosetta 模式的 Python，建议：
- 重新装原生 arm64 版 Python（从 python.org 下载 macOS 64-bit universal2 installer）
- 或者改用 conda：`conda install -c conda-forge librosa`

**方案 3：确认已装 Xcode 命令行工具**

```bash
xcode-select --install
```

按第 0 节流程跑完后，本项目实际下载并全量验证过一遍，**以下是真实结果**，你可以直接对照。

### 下载与解压

| 项目 | 实测值 |
|------|--------|
| 压缩包大小 | 1,226,192,050 字节（1.14 GiB） |
| 下载耗时 | 约 5 分钟（中途断流一次，靠断点续传补完） |
| 解压后大小 | 约 1.3 GB |
| 最终目录 | `data/genres_original/`，10 个曲风各 100 个 `.wav` |

### 全量验证结论（1000 个文件）

```
总文件数    : 1000（10 曲风 × 100 首，完全均衡）
格式        : 全部 .wav
采样率      : 全部 22050 Hz
时长        : 最短 29.93s / 最长 30.65s / 平均 30.02s
损坏文件    : 1 个
时长异常    : 10 个
```

### ⚠️ 发现的两个问题（都是 GTZAN 的已知缺陷，不是你的错）

**问题 1：`jazz/jazz.00054.wav` 损坏（NoBackendError）**

这是 GTZAN 数据集**最著名的缺陷**，几乎所有用 GTZAN 的人都踩过。
该文件在原始打包时就坏了，librosa 无法加载。

- **影响**：跑特征提取时会让整个程序崩溃
- **处理办法（二选一）**：
  - 推荐：在特征提取脚本里用 `try/except` 跳过加载失败的文件（少 1 个不影响训练）
  - 或者删掉它：`python scripts/verify_dataset.py --delete-broken`

**问题 2：`hiphop.00036` ~ `hiphop.00045` 时长 30.65 秒（标准是 30 秒）**

连续 10 个 hiphop 文件时长偏长 0.65 秒，这是 GTZAN 原始数据本身的偏差。

- **影响**：很小。30.65s 和 30s 对特征提取没有实质区别
- **处理办法**：不用管。特征提取时统一截取固定长度（比如都取前 30 秒）即可完全规避

> 💡 **这正是先跑验证脚本的价值**：如果不提前发现 `jazz.00054.wav`，
> 你会在特征提取跑到一半时突然崩溃，而且报错信息指向的代码行
> 跟真正的原因（数据损坏）八竿子打不着，排查起来非常浪费时间。

### 附：macOS 垃圾文件

GTZAN 官方压缩包是当年用 Mac 打包的，里面混了 **1000 个 `._xxx.wav` 垃圾文件**
（AppleDouble 资源 fork，每个仅 211 字节）。它们同样以 `.wav` 结尾，不过滤的话
会看到"每个曲风 200 个文件、合计 2000 个"的假警报。

本项目脚本已内置过滤，并且已用 `--clean-junk` 清理干净。

## 6. 常见问题 FAQ

**Q0：`ModuleNotFoundError: No module named 'aifc'`（Python 3.13 专属）**

这是本项目最容易卡住新手的坑，完整分析和修复见「第 0.5 节」。快速修复：

```bash
pip install standard-aifc standard-sunau -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**Q0.5：`librosa.load()` 读 GTZAN 的 `.au` 文件失败**

GTZAN 原始版是 `.au` 格式（Sun/NeXT 音频）。librosa 通过 soundfile/libsndfile 读取 AU 是**原生支持的**，
本项目实测可以正常读。如果报错，大概率不是格式问题，而是上面 Q0 的 aifc 问题。

实在读不了的话，两个替代方案：
1. 用 HuggingFace 版本的 GTZAN（里面是 `.wav`，兼容性更好）—— 下载脚本默认走的就是这个源
2. 用 pydub 批量把 .au 转成 .wav：
```python
from pydub import AudioSegment
song = AudioSegment.from_file("input.au", format="au")
song.export("output.wav", format="wav")
```

**Q1：`pip install` 卡住不动 / 超时**
换国内镜像源（见第 2 节）。如果还慢，加超时参数：
```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple --timeout 120
```

**Q2：装完 import librosa 报 numba 相关错误**
多半是 numpy 版本和 numba 不匹配。强制重装成锁定的版本：
```bash
pip install --force-reinstall numpy==2.1.3 numba==0.61.0 scipy==1.14.1
```

**Q3：`librosa.load` 读 mp3 报 NoBackendError**
说明没装 ffmpeg。回到第 3 节装 ffmpeg，装完**重启终端**让 PATH 生效。

**Q4：终端里中文输出是乱码（Windows）**
在命令开头执行 `chcp 65001` 切换成 UTF-8 代码页，或改用 Windows Terminal。
本项目的脚本内部已做 UTF-8 处理，用 PowerShell / Windows Terminal 一般没问题。

**Q5：虚拟环境激活时提示"禁止运行脚本"（Windows PowerShell）**
是 PowerShell 的执行策略限制，用这条命令放开：
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```
或者直接用 cmd 终端（`.venv\Scripts\activate.bat`）。

**Q6：能不装 gradio 吗？**
能。第一阶段（环境 + 数据）用不到它。`requirements.txt` 里它单独列在最下面，
想跳过就先只装前面的核心包：
```bash
pip install numpy scipy numba librosa soundfile audioread pydub scikit-learn joblib pandas matplotlib tqdm requests -i https://pypi.tuna.tsinghua.edu.cn/simple
```
